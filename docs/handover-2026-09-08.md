## 3. What a worker actually means

Spark Serve is the controller. Artist Twin sends immutable jobs directly to an
admitted HTTP factory on each physical DGX Spark. A factory has a durable SQLite
job store and currently admits one job. Each song launches a **fresh Docker
container with its own Python process, YuE models and CUDA context**. The HTTP
process does not hold a shared resident model. Concurrent model processes would
duplicate allocations even though their weight files are shared read-only.

The benchmark drains one node, holds the existing controller and node locks,
then schedules isolated, identified inference containers using the pinned
production runtime. It preserves artifacts and restores admission afterward.
Here **C means concurrent inference containers on one physical Spark**. It does
not measure a hypothetical shared-model batching server or several conflicting
copies of the production factory. Stage-2 batch size 2 is within one song,
not two independent requests.

The audio path is:

```text
local reference audio -> enrollment / paired 30-second stems
lyrics -> normalization / section tags -> frozen YuE request
Artist Twin queue -> admitted factory -> isolated YuE inference
Stage-1 tokens / paired codec streams -> Stage-2 codebooks
-> reconstructed stems -> vocoder stems / mix -> final processing
-> worker integrity gate -> byte-verified Artist Twin publication
```

Artist Twin's local mix step writes provenance; it does not stitch or pad the
YuE song. No expected-duration cursor or shifted assembly offset was demonstrated.

optimization boundary. It is not an absolute GPU temperature or a shutdown
claim. See [NVIDIA's temperature documentation](https://docs.nvidia.com/deploy/nvidia-smi/index.html#temperature).

**Decision:** baseline throughput, best concurrency, speedup and H0 are all
unresolved. The report's partial 1.327 successes/hour is an aborted-batch

one job is optimal, memory is the bottleneck, or 99% utilization proves saturation.
